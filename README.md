# 城市地下管网巡检养护管理系统

面向城市地下管线登记建档、巡检任务、缺陷记录、外出维修、修复验收与设施档案全流程的地下管网巡检养护管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在数据服务层里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `underground-pipeline-inspection:entries:v2` 这一项，或调用 `resetModule(模块)`。

## 管线停用联动规则（管线 / 巡检 / 缺陷）

这三个模块通过「管线编号」关联（巡检 `关联管线`、缺陷 `所属管线`），规则集中在
`src/api/core-service.ts`：

- **停用入口在管线详情**（`/pipeline/:id`）。停用后详情与列表行只读：不能再建档/复核，
  也没有重新启用入口；下方历史巡检、历史缺陷列表仍完整保留。
- **新操作一律拦截并说明原因**：停用管线上不能确认/修复/忽略缺陷，不能分配新的巡检任务，
  新建缺陷/巡检时停用管线在下拉中不可选；服务端在写事务内再校验一次，绕过页面也拦得住。
- **已经开始的任务可继续走完**：已分配/执行中的巡检允许「开始巡检、确认完成」，只拦新派工。
- **失败保留与重试**：查询或提交失败时保留上一次成功结果，空数据不当成无记录；
  空筛选结果显示「没有符合条件的记录」，与「暂无数据」是两种文案。
- **先落库者赢**：每行带 `rev` 版本号，写操作经串行队列 + CAS 提交。两人同时提交同一记录时，
  先落库的成功，后者收到 `CONFLICT` 并拿到最新行，页面回到可操作状态后可「按最新结果重试」；
  中途网络失败数据不变，可原样重试。
- **中断继续**：新建表单的草稿实时写入 localStorage，关闭弹窗或刷新后再次打开可继续填写。
- **多人演示**：开两个浏览器标签页分别操作，一页落库后另一页经 `storage` 事件静默对齐。
  页头「故障演练」开关可模拟网络失败，验证保留与重试行为。
